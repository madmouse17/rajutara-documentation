---
title: Glossary
description: "The vocabulary of Rajutara: style, piece, contour, grade rule, marker, lay and the rest."
---

The words of Rajutara. They are also the names of its types and modules, so a term here is the term in the code, the menus and these pages. The third column lists words that mean something else in this project or are easy to confuse with the term.

| Term | Meaning | Avoid |
|---|---|---|
| **Style** | A garment design as a set of pattern pieces plus its size table and grade rules. The unit a document saves. | Model, design file, project |
| **Piece** | One pattern component of a style, bounded by a closed cutting contour, carrying its notches, grainline, internal lines and annotations. | Panel, part, pattern |
| **Contour** | The closed outline of a piece: an ordered sequence of segments (line, cubic Bézier, arc). The cutting contour is the outermost; the sewing contour is the cutting contour minus seam allowance. | Outline, boundary, path, polygon |
| **Seam Allowance** | The band between sewing contour and cutting contour, with a width per segment. | Margin, offset, SA |
| **Notch** | A mark on the contour that aligns pieces during sewing. Has a shape (V, T, I, L (check), U, Box), depth and width. Box is the ASTM D6673 "castle" notch (layer 81). | Clip, snip, mark, castle |
| **Grainline** | The directed line on a piece that must align with the fabric warp during marker placement. | Grain, arrow, warp line |
| **Size Table** | The ordered list of sizes a style is graded to, with one base size. | Size range, size set |
| **Grade Rule** | The X/Y displacement of one point of a piece (contour, internal, drill hole or grainline end) from the base size to each other size. | Grading increment, growth, delta table |
| **Marker** | The arrangement of pieces of one or more styles and sizes on a fabric of given width, ready to plot or cut. | Layout, nest, lay plan |
| **Marker Table** | The canvas of the Marker workspace: the fabric band of the Marker's Material width on which pieces are placed. X runs along the marker length (the warp), Y across the width. | Canvas, desk, work area |
| **Piece Bar** | The strip of the Marker workspace that holds the piece instances still waiting to be placed: one thumbnail per Style, piece and size with the remaining count. Its order seeds Nesting. | Piece tray, palette, queue |
| **Piece List** | The Marker workspace table with one row per piece and size of the embedded Styles, where Marker-only properties (code, material, quantity, rotation, flip, buffer) are edited on the embedded copy. | Pieces Table (the PDS pane), parts list |
| **Cluster** | Two or more placed pieces of a Marker that keep their arrangement and are moved, shot and nested as one piece. While they wait, the Piece Bar shows them as one thumbnail. | Group, bundle (a Bundle is the pieces of one size request), assembly |
| **Fuse Block** | A Cluster with a border (a rectangle round the pieces or a contour that follows them, at a set gap) that Export Cut File cuts instead of the pieces, so the block can be fused before the pieces are cut. | Fusing zone, interlining block |
| **Cutting Order** | The order in which a Marker's pieces go to the cutter, with the start point and the direction of each cut. Not the Cut Order of a Cut Plan. | Cut sequence, plot order, Cut Order (that is the Cut Plan's) |
| **Bump Line** | A vertical or horizontal wall of a Marker that pieces do not cross during Nesting and Shoot. A Bump Line may also be a Cut Line, or a No Bump line that pieces may cross. | Wall, barrier, stop line |
| **Cut Line** | A Bump Line marked Cut, which the cut file cuts: a vertical one across the fabric with an overcut at each end, a horizontal one along the fabric up to the used length. The parts inside a piece and the parts shorter than the Minimal Cut Line Segment are left out. | Cross cut, split line |
| **Flaw** | A rectangle of the fabric, marked on the Marker, that Auto Nesting and the Place commands keep every piece off. A Flaw may span the whole marker length or the whole Material width. It never adds to the used length. | Defect, hole, damage |
| **Nesting** | The act of placing pieces on a marker, by hand or by algorithm, to minimise fabric length. | Packing, layout, optimisation |
| **Lay** | A stack of fabric plies cut together under one marker. | Spread, ply stack |
| **Order** | The quantities of a style per size and colour that cut planning must satisfy. | Job, production order |
| **Base Size** | The one size in a Size Table whose piece geometry is drawn; every other size is derived from it by Grade Rules. | Master size, sample size, reference size |
| **Ply** | One layer of fabric in a Lay. | Layer, sheet |
| **Plot** | Output of a marker or pieces at 1:1 scale to a plotter (HPGL/2) or to PDF, including tiled PDF for small printers. | Print, export drawing |
| **Operator** | The person using rajutara in a garment workshop: a pattern maker, grader or marker maker trained on Optitex. | User, designer, admin |
| **Turn Point** | A contour point where the line may change direction sharply. Two Turn Points with no Curve Point between them are joined by a straight line. | Corner point, anchor, node |
| **Curve Point** | A contour point that a smooth curve passes through; consecutive Curve Points shape one curve. | Spline point, control point, handle |
| **Grade Point** | A point of a piece that carries its own Grade Rule. Contour points without one move in proportion to the neighbouring Grade Points. | Rule point, cardinal point |
| **Internal Line** | A line inside a piece that is drawn, cut or sewn but is not part of its contour. | Internal, inner line, drawing line |
| **Drill Hole** | A point inside a piece that is punched or marked when the piece is cut, optionally with a diameter. | Punch, hole, button |
| **Annotation** | Text placed on a piece and plotted with it. | Label, comment, note |
| **Mirror Line** | The straight edge of a half piece about which it unfolds into the full, symmetric piece. | Fold line, symmetry line, half line |
| **Dart** | A wedge of fabric taken out of a piece, defined by two legs on the contour and a tip. | Tuck, suppression |
| **Pleat** | A fold of fabric set into a piece from the contour, defined by its fold lines, type (knife, box, axe) and depth. | Tuck, fold |
| **Track Line** | The thin dashed ghost of a Piece as it was when Track Lines was switched on, base size only, with its internals. It lives for the session and is not saved. Restore By Track Line puts the remembered shape back. | Trace, history line, undo ghost |
| **Zone** | An area of a Map Piece marked by clicking inside it (Build Zone) or by tracing the runs that confine it (Trace Zone). Create Pieces From Map turns each Zone into a Piece. | Region, area, section |
| **Map Piece** | A Piece that holds Zones: a flat sketch of the garment whose areas become the real Pieces. Pieces made from it remember their Zone, so Correct All Pieces By Map can rebuild them. | Block, master piece, base pattern |
| **Equal Segments Group** | Runs of contours or Internal Lines of one Style that stay equal while the Operator edits: in length only, or in shape as well. The first run edited leads and the others follow. | Linked segments, match group, sibling lines |
| **Stripe Group** | A number given to Pieces that share one stripe or check match in a Marker. Relate Piece To Stripes marks the point of a Piece that sits on a stripe line. | Match group, pattern group |
| **Spread Pieces** | A Piece flagged so that the Work Area and the Plot show one derived copy for each further Quantity and Pair beside it. Gather Pieces clears the flag. Not the spreading of a Lay. | Duplicate, copy pieces, array |
| **Material** | A named fabric that pieces are cut from. A Marker is made on one Material, which supplies its width, ply mode, shrinkage and cost. | Fabric type, cloth, textile |
| **Ply Mode** | How each Ply of a Material lies on the table: single (open), tubular, faced (face to face) or folded. | Layout mode, spread type, fabric layout |
| **Bundle** | The set of pieces that makes one garment of one size of a style. A Marker asks for a number of Bundles per size. | Set, kit, garment |
| **Buffer** | Extra space kept clear around a piece in a Marker. | Gap, clearance, spacing |
| **Efficiency** | The area of the placed pieces divided by the Marker width times its used length, in percent. | Utilisation, yield, usage |
| **Graded Nest** | All sizes of a piece shown or exported together, aligned at a Stack Point. | Size stack, nest |
| **Stack Point** | The point or grainline at which the sizes of a Graded Nest are aligned for display. Choosing it never changes geometry or Grade Rules. | Anchor point, reference point |
| **Rule Table** | A numbered set of Grade Rules kept with a Style, copied onto Grade Points and exchanged as an ASTM RUL file. | Rules library, rule file, RUL |
| **Cut Plan** | The Lays, each a Marker with a ply count, that together cut an Order from one Material, with the fabric length and cost they consume. | Cutting plan, spreading plan |
| **Cut Order** | The sequence in which the Lays of a Cut Plan are spread and cut, with the Fabric Rolls each Lay draws its Plies from. Optitex calls a whole plan a "cut order"; in rajutara that is the Cut Plan. | Spreading order, cutting sequence, roll plan |
| **Fabric Roll** | One roll of a Material in one Order colour as it comes from the Fabric Room, with its code, Shade, width and length. Each Ply is drawn whole from one Fabric Roll. | Bolt, piece goods, roll stock |
| **Shade** | The tone class a Fabric Roll is graded into at inspection (Optitex "Shade": A, B, C, …). The Plies of one Lay come from one Shade whenever the rolls allow. | Lot, dye lot, tone |
| **Remnant** | The fabric left on a Fabric Roll after the Cut Order has drawn its Plies from it; it goes back to the Fabric Room. | Roll end, end bit, leftover, offcut |
| **Purchase Order** | A buyer's order inside a Cut Plan: its Order (the quantities), its own markers and its own Lays. A Cut Plan holds one or more, each planned apart and compared side by side. Written PO in the interface. | Order (that is the quantities alone), job, batch |
| **Spreading Group** | Materials of a Cut Plan that are cut from one fabric together. The first Material of the group gives the width, shrinkage and cost, and a marker holds the pieces of all of them. | Fabric group, material set |
| **Cutting Table** | A table a Cut Plan can cut on: a length, a fewest and a most Plies, and optionally the one Material or Spreading Group it serves. Solve uses the longest table that fits, and the Cut Order gives each Lay to the table with the least length spread so far. | Spreading table, cutting bed, Marker Table (that is the canvas) |
| **Roll Group** | Fabric Rolls of one Material planned together because they share a width step, a shrinkage or a Shade, as the Cut Order setup asks. Each colour's quantities split over its Roll Groups in proportion to their fabric, and each group has markers of its own. | Roll batch, fabric lot |
| **Fabric Room** | The workshop's inventory of Fabric Rolls as a CSV or Excel file: code, Material, colour, Shade, width, length, shrinkage, supplier, cost and weight. A Cut Plan takes rolls from it and writes the Remnants back after the Operator confirms. | Warehouse, stock list, roll database |
| **Style Set** | A named list of pieces of one Style, each row with a name, code, description, Material, quantity, pair and shrink of its own. A Marker or Cut Plan embeds a Style Set as a Style whose pieces are the rows. | Piece group, kit, collection |
| **Measurement Chart** | The measures a buyer specifies for a Style. A measure sums parts, each taken between two points of a piece on the graded piece in every size, and each size has a buyer value with a tolerance below and above. Rajutara checks the pieces against the chart and never changes a piece to meet it. | Size chart, spec sheet, POM table |
| **Size Variation** | A further set of sizes with its own grading, kept beside the main Size Table (for example Short, Regular and Long lengths). While one is current, the Sizes Table and the grading tools edit it; Reshape Variation Grading merges them all into one Size Table of combined sizes. | Size group, size run, fit |
| **Merged Base Size** | The Base Size of a Style that Cross Grading merged into another, marked "*" in the Sizes and Grading Tables. The merged pieces keep their geometry at that size and their own deltas; they do not move in the sizes of the Style they joined. | Second base, extra base |
| **Stripe Definition** | The stripe or plaid lines of the fabric on the Marker Table: where they start, the distance between vertical stripes and between horizontal stripes, and the angle of each. With Stripe Adjust on, the match point of a placed piece lands on a stripe junction. | Check pattern, fabric grid |
| **Folded Piece** | A piece placed folded on the Marker Table: along the top or lower edge (Tubular, Folded), along the left or right edge (Faced, Folded), or as a quarter in a corner (Folded, four Plies or more). It is the half on the table side of its fold line, and the next waiting copy of the same piece is its partner, folded with it. | Half piece (that is the stored half of a Mirror Line), mirrored piece |
| **Side Buffer** | Extra Buffer on one side of a Piece: Up, Down, Left or Right of its grain frame, with the options Convex and Round Corners. The sides turn with the piece, and a mirrored copy swaps Up and Down. A Buffer Chain gives one run of the contour a Buffer of its own. | Edge buffer, offset |
| **Lane** | One of up to six bands across the Material width that Auto Nesting keeps whole Bundles in, so that the pieces of one garment come from one band of fabric when the shade changes across the width. Bundle k goes to Lane k mod n, and a piece may leave its Lane by the Lane overlap. | Column, strip, horizontal group |
| **Cut Elsewhere** | A piece of an order that another Marker of the same order cuts (Auto Save Of Markers). The Marker hides it, never nests it and does not count it as missing. | Excluded piece, hidden piece |
| **Notch Preset** | A saved notch: shape, depth, width, Top Width, Reverse and command, chosen by name in the Notch Tool and in Notch Properties. Presets live in Preferences, so every Style uses the same list. | Notch template, favourite notch |
| **Command Layer** | The one set of typed tools that batch scripts, the MCP server, Playbooks and the assistant use to read and change documents. Each tool has a name, a JSON schema, a Tool Tier and the Roles that may run it, and every change goes through Undo. | API, plugin interface, scripting layer |
| **Tool Tier** | The grade of a Command Layer tool: basic, standard or advanced. A session sets the highest Tool Tier it may call. | Level, permission |
| **Role** | Who a Command Layer session acts as: Designer, Grader, Marker maker, Cutter or Supervisor. Each tool lists the Roles that may run it; Supervisor is the default and runs everything. In the window, the Role chosen in the status bar also disables menu actions outside it; it guides the Operator and is not access control. | User level, account, permission |
| **Approval Policy** | Ask or Yolo. With Ask, the default, a tool that saves, overwrites, deletes or discards waits for the Operator's confirmation. Yolo skips the questions and the Approval Checkpoints but always keeps backups, the trash and the action log. | Auto-approve, trust mode, autopilot |
| **Untrusted Text** | Text that came from a file or an Attachment (piece names, notes, DXF text, spreadsheet cells, buyer and PO names). It reaches the caller of the Command Layer only as a numbered field of its own. It is data: it never becomes an instruction, and a destructive command never takes its target from it without the Operator's confirmation. | User input, external text, content |
| **Attachment** | A file handed to a Command Layer session: PNG, JPEG, PDF, CSV or XLSX, recognised by its content, with an id, a size limit and a hash. An Attachment counts as untrusted data. | Upload, enclosure |
| **Playbook** | A TOML recipe of named stages with parameters, checks and Approval Checkpoints, run through the Command Layer with or without a model. Its state is saved after every stage, so an interrupted run resumes, and every run writes a Run Record. | Macro, workflow, script |
| **Approval Checkpoint** | A point in a Playbook where the run stops and asks the Operator to continue, to choose or to stop. Approval Policy Yolo skips it. | Confirmation, gate |
| **Quick Action** | A named start of a Playbook with its parameters filled in, offered as one choice: for example a marker optimisation with the quick algorithm and the workshop's time limit. | Shortcut, preset, macro |
| **Run Record** | The file a Playbook run writes: the app version, the Playbook version and hash, the Workshop Profile hash, the Prompt File versions, the model id and the nesting seeds. Replaying a Run Record repeats the run. | Log, audit trail, history |
| **Workshop Profile** | One TOML file of the workshop's standards, labelled in Indonesian: seam allowance per seam type, shrinkage, ply limits, piece buffer, efficiency target and QC tolerances. Playbooks and the assistant read it, and a value without a source is reported as needing the Operator's confirmation. | Settings, factory config, template |
| **Assistant Memory** | What the assistant keeps between sessions: lessons, preferences, facts and corrections, stored on this PC in the config folder and, optionally, in a project's `.rajutara/memory/`. Document and tool results outrank the Workshop Profile, which outranks memory; a memory that contradicts either is marked stale. | History, chat log, cache |
| **Knowledge Index** | A local search index (BM25, no embedding model) over the workshop's own SOPs and buyer manuals (PDF, TXT, MD and DOCX text). The files are read and never changed, and a search returns snippets, which are Untrusted Text. | Library, wiki, vector store |
| **Prompt File** | A versioned text resource that tells a model who Rajutara is and how to answer: a core file (under 600 tokens), one per Role (under 400), one per Knowledge Skill (under 400), one per Persona tone (under 120) and one per Playbook stage. A managed override in the config folder wins over the shipped file, and its version and hash go into the Run Record. | System prompt, template |
| **Action Contract** | The rule that a model answers with exactly one JSON action per turn: a tool with its arguments, a sentence to say, or a question to the Operator with two to six choices. The Command Layer checks it against the tool schemas and the tools the stage allows before anything runs. | Output format, protocol |
| **Answer Template** | The Fluent message (`answer-<tool>`, English and Indonesian) that turns the result of a tool into the sentence the Operator reads. The numbers come from the result and are formatted by the Operator's number format; no model text goes in. | Summary, response text |
| **Prompt Preview** | Everything a prompt holds, listed for the Operator: instructions, tools, lessons, knowledge snippets, document excerpts, tool results, sizes and redactions. Before a request leaves the PC, the consent window shows this list together with the exact request, and only the Operator's Send releases it (see Consent). | Debug view, dry run |
| **Redaction** | Replacing buyer names, PO codes and prices in a prompt with placeholders (⟦BUYER_1⟧, ⟦PO_1⟧, ⟦PRICE_1⟧) before it reaches a model provider. The map stays on this PC and restores the placeholders in the model's reply. | Anonymising, masking, scrubbing |
| **Assistant** | The pane beside the workspaces where the Operator types a goal and a model works towards it through the Command Layer's tools, one Action Contract at a time. It is off until the Operator picks a Model Profile. Quick actions, the playbook runner and scenario comparison sit beside it and need no model. | Chatbot, copilot, AI |
| **Model Profile** | One named way of calling a model: Provider Kind, address, model name, sign-in header, key reference, extra headers, answer mode, limits, timeout and prices. The Operator keeps several and marks one as the default; the key itself never sits in the profile. | Connection, account, endpoint |
| **Provider Kind** | The API a Model Profile speaks: `ollama`, `llama-cpp`, `openai-compatible`, `openai-responses`, `anthropic` or `gemini`. Many vendors share one kind; Groq, DeepSeek and LM Studio all speak `openai-compatible`. | Vendor, backend, driver |
| **Preset** | A starting point that fills a new Model Profile for one provider: kind, address, sign-in header, API version and answer mode. Twelve ship. Every field it fills stays editable, and the profile does not follow later changes to the preset. | Template, default, connector |
| **Egress** | Where a request goes. Local means this PC (loopback only); Remote means any other host, the Operator's own network included. Every Remote request needs Consent. | Cloud, online, external |
| **Consent** | The Operator's Send for one Remote request, bound to the SHA-256 of its method, URL and body. It covers that request only; a retry or a changed request asks again. | Permission, opt-in, allow |
| **Knowledge Skill** | What one assistant turn knows about: a Prompt File, a short tool list, the knowledge tags searched first and the memory scope its lessons come from. Eight ship: pattern making, grading, marker, cutting room, materials, QC, file exchange and teacher, the one that explains how to do things. | Agent, plugin, mode |
| **Persona** | How the assistant speaks: a display name and a tone, Formal (Anda) or Casual (kamu). It changes wording only, never which tools run. | Character, personality, voice |
| **GUI Socket** | A listener on 127.0.0.1, off by default, that lets one local program with the token from the config folder use the running window over MCP. Every guarded change it asks for waits for the Operator in the assistant pane. | API server, remote control, port |
| **Traced Piece** | A draft Piece made by `trace_from_photo` from a photo on a reference sheet. It carries the code `TRACED` because there is no lens model, and it must be checked before cutting. | Scanned piece, digitised piece |
| **Eval Case** | A folder with a `case.toml` (goal, files to open, approval policy, checks) that `rajutara eval` runs against a Model Profile to measure how well it reaches the goal. The owner keeps the cases; nothing in the folder is written. | Test, benchmark, fixture |
