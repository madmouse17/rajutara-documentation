## [Unreleased]

### Added
- **PDS: Add Slit Along Segment** (T102, `docs/spec/02-pds.md` §13.1, Design › Add). Places notches, buttons, lines, points or Grading Points along the selected segment, or between two selected points of one contour. You set how many (Number) and how far apart (Distance), or ask for as many as fit (Number 0) or By Equal Distance, clockwise or counter-clockwise, with Skip Darts and Points On Curve. Fields that do not apply to the chosen Type are disabled and say why. It is one undo step, and the objects follow the grading the way a point added on the contour does.
- **Assistant pane** (`docs/spec/07-ui-shell.md` §16, ADR-0030, View › Assistant, `Ctrl+Shift+A`). A pane on the right of every workspace where you type a goal and a model works on the open documents through the same tools as `rajutara mcp`. Each step shows as a card: the tool and its result, Before and After pictures, and Undo for that change. Saves, overwrites, deletes, plans and playbook checkpoints wait for your Approve. Threads are kept on this computer, and the composer takes attachments. The assistant stays off until you choose a model; the first time you open the pane it looks for Ollama on this computer and lists its models.
- **Model profiles for many providers** (§16.3). Six provider kinds: Ollama, llama.cpp `llama-server`, OpenAI Chat Completions and the servers that copy it, the OpenAI Responses API, Anthropic Messages and Google Gemini. Twelve presets fill in a profile: OpenAI, Anthropic, Google Gemini, OpenRouter, Groq, DeepSeek, Mistral, Azure OpenAI, Ollama, llama.cpp server, LM Studio and Custom (for Together, vLLM, LiteLLM and other compatible servers). Every field stays editable: address, model, sign-in header, API key from an environment variable or saved in `keys.toml`, extra headers, API version, answer format, temperature, limits, timeout and prices. List models and Test connection check a profile. When a provider refuses a parameter, the profile adapts and the thread says what changed. Keep several profiles and switch between them in the pane header.
- **Privacy preview** (§16.4, ADR-0031). Only this computer counts as local. Before a request goes to any other host, your own network included, a window shows it as it will be sent (address, headers with secrets hidden, exact body), and Rajutara sends it only when you press Send, once per request. By default Rajutara replaces buyer names, PO codes, prices and paths in the request. A public host needs https, Rajutara never follows a redirect, and API keys never enter the preferences, threads or logs.
- **Knowledge skills and persona** (§16.7). Eight skills (pattern making, grading, marker, cutting room, materials, QC, file exchange, teacher) give the model a short tool list, the knowledge tags to search first and the lessons of their area. The assistant picks one from the goal and the workspace; choose another in the composer or start the goal with `@<skill>`. Preferences › Assistant sets the assistant's name and a Formal or Casual tone.
- **Roles in the window** (§16.6). The status bar shows the role (Designer, Grader, Marker Maker, Cutter or Supervisor). Menu, toolbar, palette and shortcut actions outside the role are disabled with the reason. Supervisor, the default, disables nothing.
- **Assistant Memory window** (§16.8). Lists every remembered lesson, preference, fact and correction with its scope, source and whether it is outdated, with filters and search. Forget moves entries to the trash folder after you confirm; Add lesson… adds one. The assistant also remembers your corrections and the choices you mark "Remember my choice".
- **Feedback on answers** (§16.8). Helpful and Not helpful on every answer, with an optional comment that can become a correction. Ratings stay in `feedback.jsonl` on this computer.
- **What's new and `release_notes`** (§16.2, §16.7). After an update, the pane shows the release notes of the new version once. The new tool `release_notes` returns the notes of the running version, of one version or of every release since a version, from the CHANGELOG built into the program.
- **Trace from photo, experimental** (`trace_from_photo`, §16.11, Trace From Photo…). Photograph a piece on a sheet of known size (A4, A3 or your own), mark the sheet's four corners and a point inside the piece, and Rajutara adds the outline as a new draft piece with perspective corrected. There is no lens model, so the piece carries the code `TRACED` and needs checking before it is cut. The tool refuses photos over 50 megapixels.
- **GUI socket and `rajutara mcp --gui`** (§16.9, ADR-0032). Preferences › Assistant › Local programs lets one program on this computer use the running window over MCP. It is off by default, listens on 127.0.0.1 only and needs the token the window writes to `gui-socket.json`. `rajutara mcp --gui` connects an MCP client to it. Each guarded change the program asks for waits as a card in the pane until you approve or refuse it.
- **MCP confirmations** (§16.9, MCP 2026-07-28). `rajutara mcp` now asks the client's user before a save, overwrite, delete, discard or playbook checkpoint when the client can show a form (`input_required`). The client repeats the call with the answer and a signed state that expires after 5 minutes and works once. Other clients get `confirmation_required` as before.
- **Voice input, optional** (§16.10, ADR-0033). A mic button in the composer when the separate `rajutara-voice` helper is installed. It records and transcribes Indonesian or English offline with whisper.cpp and puts the text in the composer for you to check. The helper ships as its own download for Linux, Windows 10 and 11, and Windows 7; the main program has no audio code.
- **`rajutara eval DIR`** (§16.12). Runs your own test cases, each a folder with a `case.toml` (goal, files, approval policy, checks), against one model profile and writes one JSON line per case to a local results folder. A model on another computer needs `--allow-remote`, and every request body is saved beside the results.
- **Quick strip, playbook runner and scenario comparison** (§16.5). A Quick strip after the workspace toolbars starts the quick actions of the active workspace, with a form for missing values. Playbook Runner… steps through a run with its checks, outputs, checkpoints and choices, and resumes earlier runs. Compare Scenarios… runs one stage with up to 12 parameter sets side by side. All three work without a model.

### Changed
- The Linux menu entry of the AppImage reads "Rajutara" with a capital R.
- **Controls have a visible edge.** Unticked checkboxes and radio buttons, idle buttons, text fields and combo boxes now have a 1 px border with at least 3:1 contrast against the panel and the desk, in the light and the dark theme (WCAG 1.4.11). Before, an unticked checkbox stood out from the panel by only 1.13:1.
- **Agent layer: a compact prompt** (ADR-0022, core prompt version 3). Each tool in the prompt now carries only its name, purpose and input schema. The full action schema still constrains the model's answer beside the prompt. The fixed prompt drops from 11,000–18,000 tokens per skill to 2,500–4,800, so a local model with an 8,000-token context window can follow it. New model profiles start with a 16,384-token context window; saved profiles keep their own value.

## [2.0.0] - 2026-11-06

Wave C: the v2.0 items of `docs/spec/08-v2-roadmap.md` §3.2, the v2.x items X3, X4, X6, X7, X9, X10, X13 and X14, size variations, Cross Grading and the agent command layer. Files saved by this release are native format 3, which 1.5.x and older cannot open (see Changed).

### Added
- **PDS: Notch presets and Top Width** (`docs/spec/02-pds.md` §12.1, Optitex O/26.1). The Notch Tool dialog and Notch Properties gain Preset and Save as Preset…; View › Notch Presets… renames and deletes them. A preset keeps shape, depth, width, Top Width, reverse and command. Presets live in Preferences, so every Style sees the same list. A Box notch gains Top Width, its width at the tip (empty means the width), drawn on the Work Area, in the plot and in the Marker plot and cut file.
- **PDS: Change Multiple Internal Attributes filters** (T51, O/25.1): Min and Max for notch depth, width and Top Width, and for drill-hole radius.
- **PDS: Auto Renumber** (Preferences › PDS › Copied pieces). Paste and Save Active as New give the copy the source's trailing `_n` plus one, or `_1`, and count on while that name is taken. Standard copy keeps the old naming.
- **PDS: Segment Length from both ends** (T43, O/26.1). Moving end Both ends moves each end half the change. Extend By Curve is refused with Both ends.
- **PDS: Switch Cut/Sew asks first** (O/26). Switch Cut/Sew and Switch Pieces to SEW/CUT say how many pieces change their stored line and ask to Continue, with Do not ask again. Preferences › PDS › Confirm switching between sew and cut lines brings the question back.
- **PDS: Style Sets** (`docs/spec/02-pds.md` §12.3, View › Style Set, key `4`). A Style Set lists pieces, each row with its own Code, Description, Material, Quantity, Pair and X/Y Shrink. The pane has a search field (case and accent are ignored), Create, Remove, Duplicate (`@<name>`), Description, Add Pieces (a piece may be added twice), Remove Pieces and Place, which puts only the set's pieces on the desk and arranges them for plot. Each edit is one undo step. New Marker, the Marker Creation Wizard and Cut Plan › Add Style can embed one set instead of the whole Style, and Update from Style keeps the set.
- **PDS: Production Sheet** (File › Production Sheet…, X4). An A4 PDF with the Style facts (Author, Date, Sizes, Base Size, Notes), the pieces table (Name, Code, Description, Quantity, Pair, Material, Area, Perimeter at the Base Size), a drawing of the Base Size pieces and one table per Measurement Chart.
- **PDS: Plot to DXF** (ADR-0017). The Plot dialog gains a DXF target (release 12, millimetres, colours from the Plotter Setup pens) and remembers the target used last. Translate piece names prints the names through the Piece Name Dictionary.
- **PDS: drill holes and texts per size** (O/24, O/21). Drill Hole Properties › Appearance in sizes has one check per size; Annotation Properties › Text in sizes has one field per size (empty means the main text). The plot, the graded-nest DXF, the Marker and the Grading views follow each size, and the Work Area marks a hole that is absent in the shown size with a small cross. A Base Size DXF with a rule file cannot hold this, so it writes every hole and the main text and says so in the export notes.
- **Grading: Size Variations** (`docs/spec/03-grading.md` §12.1, Grading › Sizes Table). Current Size Variation, Insert, Append, Delete and Name. While a variation is current, the Sizes Table, the Grading tools and the Graded Nest work on its sizes and deltas. Grading › Reshape Variation Grading turns the variations into one size list named `<variation size>-<main size>`, and is refused above 99 sizes. Markers and Cut Plans see the variation sizes only after Reshape.
- **Grading: Cross Grading** (§12.2, Merge Style File › Special Merge Sizes List). The Style keeps its sizes and gains the merged file's other sizes in file order. The file's Base Size is marked `*` in the size tables, and the merge is one undo step.
- **Grading: Measurement Charts** (§12.3, View › Measurement Charts, Grading › Measure Definition). Several charts per Style. A measure is the sum of its parts times a factor; a part runs between two points of one piece, taken Along Contour, Straight, Horizontal or Vertical, in every size. Tolerance − and +, a buyer spec per size with Spec and Diff rows, and an out-of-spec value that reads `OUT +5.0` as text, not colour alone. Import Spec… reads `.csv`, `.xlsx` or `.ods`; Report… and Out of Spec Report… write `.csv`, `.xlsx` or `.pdf`. Charts are saved in the Style. Nothing is resized (ADR-0004).
- **Grading: L-notches as L shapes** (§12.4, Export Graded Nest, O/26). Off by default. When on, an L notch also writes its L-shaped outline as a polyline beside its point.
- **Marker: Algorithm** (`docs/spec/04-marker.md` §6.3, §6.5, ADR-0019). Auto Nesting Setup offers Standard, Standard Quick (the first passes and compaction only) and Advanced (overlap minimisation on the no-fit polygons after a Standard start; it returns the better of the two). Advanced is the default (see Changed).
- **Marker: efficiency log and interim markers** (O/25). Auto Nesting Setup › Write efficiency log (CSV) writes `<stem>-nesting.csv` (`time_s,length_mm,efficiency_pct,placed`, one row per improvement), and Save interim markers rewrites `<stem>-interim.rjm` with the best packing at most once a minute. Both need a saved Marker.
- **Marker: bundle grouping, lanes and block options** (§6.5, Auto Nesting Setup › Grouping). Nesting According To Bundles, Groups According to Sizes, Bundles Overlap (Small, Medium, Large), Maintain Piece Orientation Within Bundles, Horizontal Groups (1 to 6 lanes across the width) with Horizontal Groups Overlap, and Block Fuse During Nesting (Regular, Nest Blocks First, Nest Blocks Last, Nest Blocks Only, Nest With No Blocks) with Separate Blocks. The Grouping and lane choices are saved in the Marker; Block Fuse During Nesting and Separate Blocks last for the session. With lanes, the bundle areas of each lane run side by side with the other lanes.
- **Marker: Edit Piece Buffer** (§5.8, Piece menu, O/19). Around, Convex, Up, Down, Left and Right, chains of the cutting line picked One by One or Start-End with their own width, and Round Corners; Apply to Selected Pieces or Apply to All Pieces, one undo step. View › Piece Buffer draws the buffered outline. A piece with no side buffer and no chain nests exactly as before.
- **Marker: folded pieces** (§5.9). Piece › Foldable Up & Down (`Ctrl+U`), Foldable Left & Right and Not Foldable (`Ctrl+Q`) set the rules of the Marker's copy. Piece › Place Folded offers the four edges and the four corners, or hold `U`, `D`, `L` or `R` while you drop or double-click a waiting piece (two keys make a corner). The ply mode decides the edges: Tubular folds on the top and bottom, Faced on the left and right, Folded on all four, and corners need Folded with 4 plies or more; the right edge needs a Marker length. A folded pair is two copies lying as one half on the fold line. Double-click it, or use Piece › Unfold, to return both. The plot and the cut file draw the half with a fold tick, and Auto Nesting leaves folded pieces where they are.
- **Marker: stripes and plaids** (§5.10). Marker › Stripe Definition… (Start X and Y, distances between vertical and horizontal stripes, the two angles, Stripe Adjust According To Set Only), View › Stripes Lines, Tools › Stripe Adjust, Marker › Relate Piece to Stripes… and Grouping › Stripe Adjust Group (`Ctrl+G`). With Stripe Adjust on, a piece with a stripe point snaps to the stripes when it is dropped, dragged alone, shot or inserted into a hole, and Auto Nesting places such pieces only on stripe positions.
- **Marker: Tilt** (§5.11). Piece › Tilt Left (`F11`) and Tilt Right (`F12`) turn the selected placed pieces by the Tilt Step of Preferences › Marker, within the piece's Max Tilt (PDS Piece Properties or the Marker Piece List, in degrees), in one undo step. Preferences › Marker › Ignore Automatic Tilt Rotations is on; turned off, Auto Nesting also tries every orientation tilted by its Max Tilt either way.
- **Marker: Auto Save Of Markers** (§6.8, Nesting menu). With it on and a Marker length set, Start AutoNesting leaves the first packing in the open Marker and nests what did not fit into `<file>-1.rjm`, `<file>-2.rjm` and so on, until every piece is placed or a round places none. Pieces that another of these markers cuts are "cut elsewhere": hidden from the Piece Bar, not nested and not counted missing. Save Only Nested Pieces (And Zero Remainders) and Write Log Report To File (one CSV row per saved marker) are options, and the summary lists the files with Open buttons.
- **Marker: Export to CAD/CAM Files…** (§9.3, File menu, ADR-0017). A DXF (release 12, millimetres) of the plot content, labels as text, one colour per Bundle and one layer per kind of element. Translate piece names uses the Piece Name Dictionary.
- **Marker: Customize Excel Report…** (§8.3, File menu). One tab per report table; each column has Show, Title, Move Up and Move Down, plus Restore Defaults. The choice is stored in Preferences, and the Excel and PDF reports follow it.
- **Marker: Piece Description** (§9.4, Preferences › Marker). Fields (Style Name, Piece Name, Code, Size, Bundle, Material, Description Text) in the order you set, Multi-Line Piece Description, Separator, Alphabetical Bundle Names, Don't Reset Bundle Numbering for Each Size, Orientation Next to Bundle Number, Auto Adjust Description Text and Show Piece Description Text in non-flipped form. The table, the plot, the cut file labels and the DXF export follow.
- **Cut Plan: Purchase Orders** (`docs/spec/05-cutplan.md` §11, Optitex O/26.1). A plan holds one or more POs, each with its own Order, quantities, markers and Lays. The Plan pane lists them with Add PO, Duplicate PO, Rename and Remove PO (the last one stays). Solve and Nest Markers act on the selected PO; Solve All POs and Nest All POs act on every PO, each in one undo step. With two or more POs the Results pane shows a PO comparison (one column per PO and a Total) above the selected PO's markers and Lays, and the reports carry one set of sections per PO plus the comparison.
- **Cut Plan: several Styles and Materials** (§12). Cut Plan › Add Style… adds a Style from PDS or a file, whole or as one Style Set, and each colour line names its Style; Styles and Materials… lists them and adds a Material. Every Material is planned on its own unless a Spreading Group cuts several from one fabric.
- **Cut Plan: Spreading Groups…, Cutting Tables… and roll grouping** (§12). A Spreading Group cuts its Materials from one fabric (the first Material's width, shrinkage and cost), so its markers hold the pieces of all of them. Cutting Tables (name, length, plies, optional fabric) give a fabric the limits of its longest table, and the Cut Order puts each Lay on the fitting table with the least fabric spread so far. Roll grouping in the Cut Order pane splits each colour over groups of rolls by width step, shrinkage and shade, each planned at its own width with its own markers.
- **Cut Plan: Fabric Room** (§13, Cut Plan › Fabric Room…; the file is set in Preferences › Cut Plan). A roll inventory shared by plans, in `.csv` or `.xlsx`: Add, Remove, Import, Export, filtered to the plan's Materials and colours. Take Rolls copies rows into the plan. Return Remnants asks first, then writes the Cut Order's remnants back: rolls get shorter and lighter, and used-up rolls are removed.
- **Cut Plan: Customize Report…** (§14). Hide, rename and reorder the columns of every report table, in the CSV and the PDF alike.
- **Spreadsheet imports read `.xlsx` and `.ods`** as well as `.csv` (X14): Cut Plan quantities and Fabric Rolls, the Fabric Room, Measurement Chart specs and the Piece Name Dictionary. The first sheet is read.
- **Preferences search** (`docs/spec/07-ui-shell.md` §10, O/24). A field above the page list finds a setting by its name in the UI language or in English, ignoring case and accents; results read "Page › Field".
- **Tools › Piece Name Dictionary…** (O/21.4). A Name → Translation table with Add, Remove, Import and Export (`.csv` or `.xlsx`), stored in Preferences. The PDS and Marker plots and Export to CAD/CAM print the translation of an exact name when Translate piece names is on.
- **Larger pointers on HiDPI screens.** Tool pointers are drawn at 48 px instead of 32 px from a 1.5× display scale up.
- **`rajutara batch SCRIPT`** (`docs/spec/07-ui-shell.md` §1.1, ADR-0016). Runs a script with no window: one `@COMMAND /KEY=VALUE` per line, with the Optitex Marker batch names where Optitex has the command (`@OPEN`, `@NEST`, `@SAVE`, `@PLOTTER`, `@REPORT`, `@EXPORT` and others) and menu names for the Style and Cut Plan commands (`@OPENSTYLE`, `@EXPORTGRADEDNEST`, `@PRODUCTIONSHEET`, `@SOLVE`, `@NESTMARKERS`, `@CUTPLANREPORT` and others). An unknown command or key stops the script before anything runs (exit 1). A failed line prints its error and the script goes on unless `@XOE` came first (exit 2). Saves, overwrites and deletes need `--yes`. Options: `--log FILE`, `--json`, `--role ROLE`, `--root DIR`.
- **`rajutara mcp`** (ADR-0020). Serves the command layer to an MCP client over stdin and stdout (protocol 2026-07-28, plus the 2025-11-25 and 2025-06-18 handshake). `--tier basic|standard|advanced` limits the tools it lists. The server makes no network call.
- **`rajutara playbook`** (ADR-0021): `list`, `show`, `start`, `step`, `resume`, `replay`, `quick` and `compare`. Four playbooks ship: `impor-periksa` (Import and check), `qc-pola` (Pattern QC), `pesanan-siap-potong` (Order to ready-to-cut) and `optimasi-marker` (Marker optimisation). A run saves its state after every stage in the assistant folder, stops at an approval or a choice (exit 3), and `replay` repeats it with the recorded parameters and nesting seeds. `compare` runs one stage over several parameter sets and changes no document.
- **`rajutara kb`**: `add`, `search`, `list` and `remove` keep a local knowledge index of SOPs and buyer manuals (PDF with a text layer, DOCX, TXT, MD), searched by word ranking (BM25). `remove` needs `--yes`.
- **The agent command layer** (`docs/spec/07-ui-shell.md` §15, ADR-0020) behind batch, MCP and playbooks: 85 typed tools with JSON schemas, covering documents, PDS, grading, Marker, Cut Plan, costing (fabric consumption, cost per garment), QC checks, playbooks, the knowledge index and memory. Roles: Designer, Grader, Marker maker, Cutter and Supervisor (the default, which runs everything). Every change goes through the document's Undo; a plan, a playbook stage or a PDS tool call is one undo step per document.
- **Workshop profile** `profil-bengkel.toml` (Indonesian labels): 13 shop standards (seam allowances, shrinkage, ply limits, piece buffer, efficiency target, nesting time, QC tolerances) that playbooks use as defaults. None has a source yet, so every one is reported as "perlu konfirmasi operator" (needs operator confirmation) until the shop fills in its source.
- **Assistant memory and prompt files** (ADR-0021, ADR-0022). `memory_learn`, `memory_recall` and `memory_forget` keep lessons, preferences, facts and corrections on this computer, in `<config>/rajutara/assistant/memory/` or in a project's `.rajutara/memory/`. Prompt files (a core prompt and one per role) are versioned, and a shop's own copy in `<config>/rajutara/assistant/prompts/` wins over the shipped one. A model must answer with one JSON action per turn, which the layer checks against the tool's schema, role and tier. This release makes no model call.

### Changed
- **Native format 3** (ADR-0018). Every Style, Marker and Cut Plan this release saves is format 3. rajutara 1.5.x and older refuse such a file with "made by a newer rajutara (format version 3; this build reads up to 2)" instead of dropping data. Files from 1.5.x and older open as before, and an older Cut Plan becomes one Purchase Order. The app updates itself, so update every PC that shares files at the same time.
- The welcome card shows the version beside the name, for example "Rajutara 1.5.1".
- The window title, Help › About, the start-up error and the file-type filters spell the name "Rajutara" with a capital R, like the welcome card. `rajutara --version` and the command-line output keep the lower-case program name.
- **"Cut Plan" is two words** in the menu, the preferences page and the reports: Generating a Cut Plan Report (CSV) and (PDF); "Laporan Rencana Potong" in Indonesian. The command palette still finds the Optitex spelling.
- **PDS geometry that was approximated is exact** (`docs/spec/02-pds.md` §12.6). Build Piece points on an Internal Line take the grading interpolated along it. Remove Excess Cloth turns the internal lines, drill holes and texts of the moved region with their Grade Rules. Convert Sew Internals To Seam moves darts, pleats and the mirror line onto the new sew line, or keeps them internal and says why. A notch re-anchored by a point edit keeps its place in every size. A paste between Styles with different Base Sizes keeps every size where it was. Extend in Parallel joins a neighbour it cannot reach with a straight step and names the point. Pleat Lines keep their geometry, since no public source describes it.
- **Marker: plural forms and UTC labels.** Counts read "1 piece" and "2 pieces". The Auto Save log column is `date_utc`, and the report and plot label reads "Date (UTC)".
- **Marker: the live Efficiency of Auto Nesting** is measured the way the result is, so the progress no longer reads higher than the outcome.
- **Marker: Advanced is the default Algorithm** (`docs/spec/04-marker.md` §6.4, ADR-0019). Auto Nesting, the Auto Nest Queue, `@NEST` without `/AL` and `marker_nest` without `algorithm` use Advanced, which beat Standard on all five ESICUP benchmarks by 2.54 points on average (numbers in §6.4). Standard and Standard Quick stay in the Algorithm list.
- **Marker: Update from Style** counts the folded pairs it unfolds, in its preview and in its notice, checks the source files again before it answers, and names a source file that is missing.
- **Marker: more columns.** The Piece List gains Max Tilt (°), Folding and Side buffers; the report gains Lane in Order and Tilt (°) and Folded in Pieces. Piece List lengths use the working unit. The Auto Nest Queue gains Algorithm and Block Fuse columns.
- **Cut Plan reports with several POs** put the PO name before each section and name CSV files `<stem>-<po>-<part>.csv`; Save Markers writes `<stem>-<po>-M<n>.rjm`. A one-PO report is the same as before.
- **Cut Plan: "Setup changed: solve again".** After a change of Spreading Groups, Cutting Tables or roll grouping on a solved plan, the status bar shows this field; a click runs Solve All POs. The markers of a group left without Materials keep the fabric they were cut from.
- **Reading workbooks adds one dependency**, `calamine` 0.38 (ADR-0006 line in `Cargo.toml`); the `.xlsx` writer is still rajutara's own.

### Fixed
- **Marker Piece List and Order pane: typed and dragged numbers stick.** The Quantity, Buffer and Bundles cells went back to the stored value while you typed or dragged. They now keep the value and apply it once, on `Enter`, at the end of the drag or when you click away; `Esc` drops it.
- **PDS: a notch in the seam allowance of a sew-line piece can be selected.** Picks now test the cutting line, so Select and Properties reach the notch.
- **Report PDFs keep a heading with its drawing.** A drawing that does not fit moves to the next page together with its heading.
- **Cut Plan: the totals of an empty order read 0.00**, not -0.00.

### Security
- **Spreadsheets are read within fixed bounds.** A sheet file over 20 MB, an `.xlsx` or `.ods` that unpacks to more than 256 MB, an `.xlsx` that declares more than 1 000 000 shared strings and a cell beyond row 100 000 or column 1 000 are refused, and at most 1 000 000 cells are read. Old `.xls` workbooks are not read at all: their format lets a small file ask for gigabytes of memory. Save them as `.xlsx` or `.csv`.
- **Agent sessions stay in their folder** (`SECURITY.md`). `batch`, `mcp`, `playbook` and `kb` reach only files inside `--root`, the current folder by default. A network share or device path (`\\server\share`, `\\?\UNC\…`, `\\.\…`) is refused before the file system is touched, so Windows never logs on to a share that a crafted file names.
- **Approvals are used once.** Under Ask, a save, overwrite, delete or discard needs the operator's approval for that operation and that target, and the approval is spent by the call; an approved plan covers that one run. Plans and playbooks refuse undo and redo steps.
- **File text is untrusted.** Text read from files, file names included, reaches a model only in a separate untrusted field, and a guarded target that came from file text is flagged as such in the question and in the safety note.
- **Backups stay for a day.** Every overwrite through the command layer first writes `<file>.<YYYYmmdd-HHMMSS>.bak`. A backup younger than 24 hours is never removed, however many saves follow; of the older ones, the newest 10 are kept. Deletes move the file to `.rajutara-trash/` beside it. The trash folder and the action log refuse links and pipes, and a planted backup name can no longer stall a save.
- **Attachments are read from the opened file with a hard size cap**, so a device or a file that lies about its size cannot make the read run on.
- **MCP: a tool that panics** answers with an internal error, and the server then refuses every write tool until it is restarted.

## [1.5.1] - 2026-11-04

- **Marker: Auto Nesting runs in its dialog.** Start shows elapsed time against the Time limit, the best length and Efficiency so far and the pieces placed, with **Stop** (`Esc`); a summary follows. Auto Nesting Setup has **Save**.
- **Right-click menus in the Work Area** (`docs/spec/02-pds.md` §6.7). The object under the pointer is selected first, then a menu offers what applies to it: on a segment Add Point at Midpoint, Add Point on Contour, Notch, Segment Length, Add Seam, Rotate to Horizontal and Baseline Parallel to Segment; on a point its properties, Toggle Grade/Curve Point, Notch on Point, Move Point and Delete; on a piece Piece Info, Lock, rotate, flip, copy, cut, remove and delete; on the bare desk Select, Paste, Select All, All to Desk, Zoom All and the Piece Information Text and Guide Lines checks. A Draft in progress keeps the right button for its arc.
- **Properties follows the pick** (`docs/spec/02-pds.md` §4.3). A pick on the canvas brings the Properties tab to the front of its panel without taking the keys from the canvas, the section of the object picked last comes first, and a point, notch or line pick folds the Piece section into one `Piece: <name>` line. Preferences › Tools › Show Properties when picking turns it off.
- **Edit › Undo and Redo name the command** they act on (`Undo: Move piece`), in the menu and in the toolbar tooltips.
- **Tool pop-ups match Optitex** (`docs/spec/02-pds.md` §4.3): Alt+click with the Dart tool asks Width, Depth, Overlap, Drill Distance and Drill Radius and adds the dart there; the Seam dialog has Start and End Corner and Set Last Width; Walk Options has Skip Open Pleats in the Optitex order; Notch Properties has Reverse (L notch); Add Point on Contour has Distance According To Grading Points and Move Along Contour; Alt+click with Create Parallel on a segment asks the distance for that segment; Piece Properties has Task Pieces (Selected or All) and an Adjust button for the label; Marker Properties shows the Total Pieces Area.
- **Notches plot and preview in their real shape** (I, V, T, Box, U and L with Reverse) instead of one depth line.
- **Marker: Fix on Marker** (Piece › Fix on Marker, Unfix Selected, Unfix All, and the Pieces cell menu; `docs/spec/04-marker.md` §5). A fixed piece shows a pin, refuses drags, Shoot, nudges and turns with a notice, and stays where it is during Auto Nesting even when Keep placed pieces is off. Returning it to the Piece Bar frees it; one Undo puts it back fixed. Files written before 1.4.0 load with nothing fixed.
- **Marker: Marker › Marker Definitions…** opens the Marker Properties fields as a dialog; OK applies them as one undo step. **Marker › Report…** shows the Report pane, also when it was closed.

### Changed
- The keypad shortcuts are back (`docs/spec/07-ui-shell.md` §6.2): `Num+` zooms in, `Ctrl+Num+` zooms by rectangle, `Ctrl+Shift+Num+` toggles the rulers and `Shift+=` flips horizontally, told apart from the main-row keys by the physical key. `Plus`, `F7`, `Ctrl+Shift+=` and `Alt+=` keep working.

The Indonesian labels translate the new names. The menu opener of the docked pane is now Marker Properties; Marker Definitions… is the dialog.
- A piece dragged from the Pieces Window onto the canvas lands with its centre on the drop point.
- Sizes Table: Change Size Order moves the colour, line type, thickness and visibility with the size name.
- Move Point Along Contour slides a vertex from Grade Point to Grade Point, passing the Turn and Curve Points between them and taking its new place in the contour; it used to stop at its two neighbours. A piece with fewer than two other Grade Points stops at Turn Points instead. On a circle the vertex slides between its two neighbours, with a single stop it may go round the whole outline, and a click off that stretch keeps the vertex picked up.

### Fixed

## [1.1.0] - 2026-11-01

Renamed from optirust to **Rajutara** (*rajut* = knit, *tara* = balanced). Native files are now `.rjx` / `.rjm` / `.rjc`; the old files still open.

### Added
- Start-up splash like LibreOffice's: a small (640 × 262), centred, borderless window with the owner's artwork, a real progress bar and a status line (language, icons, modules, layout, each file argument), shown at least 600 ms. It then becomes the workspace window in one frame (decorations on, no fade). The workspace opens **maximized** on first run; after that the size, position and maximized state of the last quit are restored from `window.json` in the config directory. `--smoke` still opens one fixed 1280 × 800 window with no waiting, so `first_frame_ms` still measures the time to a usable canvas.
- Help › About credits the artwork to the project owner.
- History pane: hover a row to preview that step on the canvas (read only, nothing is undone), piece names and a relative time ("2 min ago") on each row, a disk mark on the row where the document was last saved, and a session-only "Compare with before" toggle that draws the pieces the last command touched as dashed grey ghosts of the previous step. `History::peek`, `History::entries`, `History::saved_generation` and `Command::touched` are new in `rajutara-core` (additive); `Document::mark_saved` now records the saved generation in the `History`.
- **Theme mode.** The theme can now follow the operating system: `System` is the new default next to `Dark` and `Light`, applied every frame so an OS change shows at once (dark where the system does not say; Windows 7 reports light). A three-button control (System, Dark, Light) sits at the far right of the menu bar; View › Theme and Preferences › Appearance stay in step with it. Preferences are now version 2; a saved `Light` or `Dark` is kept, and a 1.0 build refuses the newer file instead of misreading it.
- **Update check and self-update** (`docs/spec/07-ui-shell.md` §14, ADR-0015). Once a day at start-up, silently, Rajutara asks GitHub for the latest release (`update.repo`, default `madmouse17/rajutara`; Preferences › General switches it off). While a newer release exists an orange **Update available · v1.x** button appears left of the theme control and opens a dialog with the release notes and **Download and Install**; Help › Check for Updates… checks on request and always answers. Linux replaces the AppImage atomically and offers **Restart Now**; Windows runs the `.msi` through `msiexec` after **Install and Close**. New dependency `ureq` 3 (`rustls`, `json`; no OpenSSL, no async runtime); `deny.toml` and `about.toml` allow `CDLA-Permissive-2.0` (the `webpki-roots` data) and skip the duplicate `getrandom` 0.2. Debug builds honour `RAJUTARA_FAKE_UPDATE=1.9.9` to show the button without a request.
- **Welcome screen.** While PDS or Grading has no document, the Work Area shows a card with the logo, **New Style**, **Open…**, **Import DXF…**, **Open sample "Kaos Lengan Pendek"** and the five newest recent files. The sample is compiled into the program and written to `samples/` in the config directory each time it is opened.
- **File › Close** (`Ctrl+Shift+W`) closes the active document. A document with unsaved changes asks Save / Don't Save / Cancel first (`Esc` is Cancel); its autosave file goes with it. Quitting and the window's close button ask the same way.
- **File › Open Recent** keeps the newest 10 files of each kind (Style, DXF, Marker, Cut Plan), groups them by kind, moves a file to the front on every open and save, and greys out files that are gone. It was a single list of 8.
- **Drag and drop:** files dropped on the window open by extension (`.rjx`, `.rjm`, `.rjc`, `.dxf`); any other file gets a notice.
- **Toolbox search** (View › Search Tools): filters the tools live by English, Indonesian or Optitex name; `Enter` runs the first match, `Esc` clears; `/` while the Toolbox pane is focused, or typing with keyboard focus on a tool button, starts the search. It has no chord: `Ctrl+Shift+F` stays Optitex's Fold Out.
- **Renamed from optirust.** Files with the old `.optx`, `.optm` and `.optc` extensions still open (File › Open, drag and drop, command line; the open dialog lists them under "Legacy optirust files"); they open untitled and Save writes `.rjx`, `.rjm` or `.rjc`. On the first run the old `optirust` config directory (preferences, layouts, window) is copied into `rajutara` once. The AppImage registers MIME types for all six extensions.
- Toolbar and Toolbox tooltips read `Name  · shortcut  · Optitex: name`.
- `Ctrl` + wheel pans the canvas horizontally and `Shift` + wheel vertically; the wheel map is in `docs/spec/07-ui-shell.md` §4.1. Ctrl + wheel no longer zooms; pinch still does.

## [1.0.0] - 2026-11-01

First release. Clean-room apparel CAD for Linux (reference) and Windows 7+ (cross-built), see `docs/adr/`.

### Added
- **PDS** workspace: 89 pattern tools (drafting, points, notches, seams, darts, pleats, walk, mirror, split/join, fullness, spiral, gusset), Pieces/Properties/History panes, Plot (tiled A4, A0, HPGL/2).
- **Grading** workspace: Size Table, Grade Rules, Rule Table, Graded Nest view, 29 grading tools, ASTM graded-nest + RUL export.
- **Marker** workspace: manual placement (drag, rotate, flip, bump, Shoot), automatic nesting engine (no-fit polygons by ring convolution, bottom-left fill, simulated annealing; deterministic by seed; `Stop::Time` is a hard wall-clock limit), marker report, HPGL/2 plot and cut file.
- **Cut Plan** workspace: orders (ratio mode, CSV import), lay planning solver, nesting, consumption and cost, Cut Order with Fabric Rolls (sequence, roll allocation, remnants), CSV/PDF reports.
- Interchange: ASTM D6673 / AAMA-292 DXF import and export, RUL grade-rule files; native `.rjx` / `.rjm` / `.rjc` (zip + JSON, format 2).
- Shell: dockable panes, command palette, keyboard shortcuts, light/dark theme, English and Indonesian UI, autosave with crash recovery, `--smoke` self-check.
- Packaging: Linux AppImage; Windows x64/x86 `.zip` (portable) and `.msi` (installer) with optional Mesa software OpenGL, Windows 7 SP1 through Windows 11.

### Known limits
- Windows builds are verified under Wine and the import gate only; real-hardware run pending.
- 3D (Runway equivalent) is interface-only (ADR-0005).
- Vendor cutter drivers are not included; the cut file is generic HPGL/2 only.
